치이카와 타이머 3종 — 최종 Python 배포본 재현 명세

1. 기준과 적용 범위
이 문서는 최종 배포 ZIP의 실제 코드 동작을 수치로 풀어 쓴 명세입니다. 과거 React/Godot 데모 요구가 아니라 최종 Python+PySide6 앱을 기준으로 합니다. 구현과 문서가 다르면 첨부 reference/chiikawa_timer.py를 기준으로 합니다.
Windows64비트, Python3.10 이상, 검증 환경Python3.12, PySide6-Essentials==6.12.0 / PySide6-Addons==6.12.0. QtMultimedia, QtTest가 필요합니다.
타이머는 데스크톱 앱입니다. 웹 페이지의 컨테이너나 브라우저 화면을 만들지 않습니다. 일반 사용은 한 프로세스당 캐릭터 한 마리이며 별도 ‘캐릭터 추가/전체 삭제/위치 편집’ UI는 없습니다. 과거 시연용 다중 캐릭터 기능을 혼합하지 않습니다.
기존 기준 환경의 화면 배율이나 렌더러 차이를 감안하더라도 논리 픽셀 위치, 원본 이미지, 프레임 순서, 상태 전이는 유지합니다.

5. Countdown 데이터와 시계
@dataclass Countdown 기본 duration=900, remaining=900, state='ready', deadline=0, finished_at=0.
clock=time.monotonic 사용. 테스트를 위해 TimerPet(clock=...)로 가짜 시계 주입 가능해야 합니다.
start(seconds,now): seconds는finite 및1<=seconds<=10800. 잘못된 값ValueError. duration=remaining=seconds, deadline=now+seconds, state='running', finished_at=0.
tick(now): running에서만 remaining=max(0,deadline-now). 0이면state='finished', finished_at=now, 완료true를 한 번 반환. 이미finished면false.
pause_resume(now): 먼저 tick(now) 호출. 아직running이면 paused. paused면deadline=now+remaining, state='running'. tick 중 완료되면 true반환하여 complete()가 호출되도록 함.
stop():state='ready', remaining=duration, finished_at=0. 앱은player.stop과update도 수행. 원/시간/추격자는 즉시 숨김.
progress=clamp(1-remaining/duration,0,1).
fade(now): ready0, running/paused1, finished=max(0,1-(now-finished_at)/1.8).
QTimer PreciseTimer, interval16ms. 60fps에 가까운 화면 갱신이지만 남은 시간 계산은 타이머 호출 횟수가 아닌deadline 기준.

7. 원형 진행 표시
반지름R=103, 중심C=(190,190), stroke9, 둥근선끝RoundCap.
track색상=#e5e9e7→#f7d3d7을progress로RGB보간.
진행색 urgency(p):
 p<0.55이면#8dcfa8→#eeb45b, fraction=p/0.55.
 그외#eeb45b→#e6454a, fraction=(p-0.55)/0.45.
각채널round(a+(b-a)*fraction). 이미지 색이나 세이렌 표정 변경 없음.
orbit(p,offset): angle=-pi/2+p*2*pi+offset; 좌표C+(cos(angle)*R,sin(angle)*R).
화면y축이아래로양수이므로0에서위,0.25에서오른쪽,0.5에서아래,0.75에서왼쪽,1에서위. 시계방향한바퀴.
progress>0일때QPainterPath.moveTo(orbit(0)), i=1..128에lineTo(orbit(progress*i/128)). 남은구간이아닌elapsed진행구간의누적표시.
원과숫자는p.setOpacity(fade) 범위내에서그린뒤restore. 캐릭터와완료색종이에fadeopacity를전파하지않음.

20. Python 소스와 Windows 바로가기 배포
프로그램 로직 chiikawa_timer.py, requirements.txt, create_shortcut.py, chiikawa_timer.ico와 assets를 같은 프로그램 폴더에 둡니다.
최초 설치: py -m pip install -r requirements.txt. 최초 바로가기 생성: py create_shortcut.py.
여러 Python 환경이 있을 경우 py -3.12로 두 명령의 버전을 맞추세요. 바로가기 생성기는 sys.executable 옆의 pythonw.exe를 사용하며 임의의 다른 Python을 탐색하지 않습니다.
create_shortcut.py는 Windows 표준 Shell COM API IShellLinkW와 IPersistFile을 ctypes로 호출합니다. 추가 Python 패키지가 필요하지 않습니다. 실제 앱의 Qt 의존성은 검사합니다.
바로가기 파일 이름은 ‘치이카와 타이머.lnk’, 기본 생성 위치는 프로그램 폴더입니다. --output으로 원하는 경로를 지정할 수 있습니다. 생성 후 바탕화면에 복사 가능.
TargetPath=현재 인터프리터 옆 pythonw.exe 절대 경로.
Arguments=큰따옴표로 감싼 chiikawa_timer.py 절대 경로. 공백/한글 폴더를 지원해야 합니다.
WorkingDirectory=코드와 assets가 들어 있는 프로그램 폴더 절대 경로.
IconLocation=같은 폴더 chiikawa_timer.ico, 아이콘 index0. 우사기 공부 프레임을 사용한 투명 아이콘입니다.
ShowCmd=1. pythonw는 콘솔 없이 실행하며 Shell이 독립 실행합니다. 생성용 터미널을 닫아도 타이머는 유지됩니다.
폴더 이동/Python 경로 변경 후에는 create_shortcut.py를 다시 실행해야 합니다. 바탕화면으로 .lnk만 복사하는 경우 프로그램 폴더는 이동하지 않습니다.
배포 ZIP에는 제작자 PC에서 만든 .lnk를 넣지 않습니다. 사용자마다 경로가 달라 그대로 공유하면 깨지므로 사용자 PC에서 생성하도록 합니다.
BAT 파일, PowerShell 파일, 빌드된 EXE, 별도 런처 설치 프로그램을 포함하지 않습니다. 실제 Python/Qt가 사용하는 바이너리에 대한 Windows 보안 정책은 여전히 적용됩니다.
종료는 기존 Qt 앱의 메뉴/트레이 종료를 사용합니다. pythonw 프로세스를 강제로 종료하면 앱도 종료됩니다.
SHA256.txt는 실제 결과 파일과 자산의 해시로 생성하고 .lnk는 제외합니다. 개인 경로/설정/계정 정보를 포함하지 않습니다.
출처/폰트 라이선스/Qt 라이선스 안내와 기존 11개 기능 테스트는 보존합니다.
